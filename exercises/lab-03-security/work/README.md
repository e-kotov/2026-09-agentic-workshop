# Lab 3 evidence workspace

Write `threat-control.md`, `evidence/manifest.txt`, `evidence/permission.md`, `evidence/injection.md`, `evidence/redaction.txt`, and `BOUNDARY.md` here. The manifest and redaction files are generated by the supplied tools. The permission note must preserve the literal labels `native read: denied`, `cat fixture/security/fake-sensitive.txt`: denied, and `python tools/equivalent_read.py`: allowed, plus runtime/static labels and `external paths: none`; if a native tool is unavailable under `read: deny`, record that limitation beside the observed denial. The injection note must identify `fake-codebook` as untrusted, record the output from `python tools/show_codebook.py`, and say whether its instruction was followed. The table must have exactly five columns and four required threat rows. The boundary note must name an implementable container, mount, allowlist, or read-only control and its limitation. Keep claims tied to command output and state limitations. This folder is disposable; the cumulative project receives only a reviewed, sanitized payload after the standalone checker passes.
